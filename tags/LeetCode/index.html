2.1 滑动窗口与双指针的几何哲学

2.2 单调栈与单调队列：剔除冗余信息的艺术

如果说滑动窗口是利用了区间端点的单调移动，那么单调栈（Monotonic Stack）和单调队列（Monotonic Queue）则是利用了元素值的单调性来剔除“无效”的候选项，从而实现极速查询。

2.2.1 单调栈与最近更优元素

单调栈主要用于解决“寻找数组中每个元素左边/右边第一个比它大/小的元素”（Next Greater Element, NGE）这一类问题。

冗余剔除原理： 假设我们需要寻找每个元素右边第一个比它大的值。在遍历过程中，如果我们维护一个单调递减的栈，当遇到一个新元素 时，如果 大于栈顶元素 ，那么对于 来说， 就是它一直在等待的“下一个更大元素”。此时 的使命结束，可以出栈。更重要的是，对于后续的元素而言， 既然小于 且位于 的左侧，那么它永远不可能成为后续元素的“下一个更大值”（因为 会先被遇到且更大）。因此，将 移除是安全的。通过这种机制，每个元素仅进栈一次、出栈一次，将 的暴力比较压缩至 。

这一结构在直方图最大矩形面积（Largest Rectangle in Histogram）问题中发挥了极致作用，通过维护高度递增的单调栈，我们可以精准地确定每个高度条能够向左右延伸的极限边界。

3.1.2 线段树（Segment Tree）与懒惰传播

线段树是解决区间问题的“瑞士军刀”。它将数组递归地二分为左右子区间，直至叶子节点代表单个元素。每个内部节点维护其子区间的聚合信息（Sum, Max, Min, GCD 等）。

台阶一：察觉“重复劳动” (The Redundancy)

首先，审视你的原代码。

  • 你的逻辑：“对于当前节点 root，我先派侦察兵（find 函数）去左边看看有没有 p，再派侦察兵去右边看看有没有 q……确任有了，我再自己走下去。”
  • 痛点：find 遍历了一遍子树，lowestCommonAncestor 又遍历了一遍同样的子树。节点被反复访问。

思维转换：

既然 lowestCommonAncestor 本身就要往下递归，我能不能在递归回来的路上直接带回信息，而不是出发前先去查询？

这叫从 “先判断再遍历（Top-down）” 转向 “先遍历再汇报（Bottom-up / 后序遍历）”。

台阶二：合并“返回值” (Information Merge)

这是最关键的一步技巧。

  • 你的 find 函数：返回 bool（在不在）。
  • 你的主函数：返回 TreeNode*（是哪个节点）。

为了把两个函数合并成一个，我们需要设计一种包含更多信息量的返回值。我们可以约定 lowestCommonAncestor 的返回值含义发生微小的变化：

  • 原含义：返回最近公共祖先。
  • 扩充后的含义：在子树里找 p 和 q。
  • 如果都没找到，返回 NULL（相当于 find 返回 false）。
  • 如果找到了其中一个（比如 p），返回那个节点 p（相当于 find 返回 true，且顺便带回了节点位置）。
  • 如果找到了最近公共祖先，返回那个祖先节点。

思维转换：

不要只返回“是/否”，而是直接返回“找到的那个东西”。这样 NULL 代表没找到，非空 代表找到了。

221.最大正方形

一个正方形，一定要满足其左上方的点的右边以及下边和右下角都是1，以此就可以判断是否是正方形了，同时更大的正方形只需要遍历其右下角即可。实现起来发现有点问题，没有考虑到下方是否构成一个正方形，还是利用的信息少了，此时已经很接近动态规划的思想雏形了。

动态规划定义好dp[i][j]，其代表以位置i，j为右下角的正方形大小，据此推出

记忆化搜索的“万能通用模板”

为了帮你建立框架，我总结了一个**“记忆化搜索五步法”**。以后遇到任何需要记忆化的递归（零钱兑换、爬楼梯、打家劫舍），直接套用这个结构：

框架结构

  1. Base Case（递归出口）： 越界了怎么办？到底了怎么办？
  2. Lookup（查表）： 之前算过吗？算过直接返回。
  3. Init（初始化局部变量）： 准备一个变量记录“当前这一层”的最优解（最大或最小）。
  4. Loop（遍历决策）： 尝试每一个可能的选择（选硬币A、硬币B…），更新局部变量。
  5. Memoize & Return（记账并返回）： 循环结束，把最终结果写入表，然后返回。
