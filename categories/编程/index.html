236.二叉树最近公共祖先

简单粗暴的递归，采用的是中序遍历，同时返回的信息较少，只能一次次遍历

这是一个非常好的问题！从直观的暴力解法（）进化到优雅的递归解法（），其实只需要跨越三个思维台阶。

一旦你掌握了这个思维路径，以后遇到很多树的题目（比如二叉树直径、最大路径和）都能迎刃而解。

台阶一：察觉“重复劳动” (The Redundancy)

首先，审视你的原代码。

  • 你的逻辑：“对于当前节点 root，我先派侦察兵（find 函数）去左边看看有没有 p，再派侦察兵去右边看看有没有 q……确任有了，我再自己走下去。”
  • 痛点：find 遍历了一遍子树，lowestCommonAncestor 又遍历了一遍同样的子树。节点被反复访问。

思维转换：

既然 lowestCommonAncestor 本身就要往下递归，我能不能在递归回来的路上直接带回信息，而不是出发前先去查询？

这叫从 “先判断再遍历（Top-down）” 转向 “先遍历再汇报（Bottom-up / 后序遍历）”。

台阶二：合并“返回值” (Information Merge)

这是最关键的一步技巧。

  • 你的 find 函数：返回 bool（在不在）。
  • 你的主函数：返回 TreeNode*（是哪个节点）。

为了把两个函数合并成一个，我们需要设计一种包含更多信息量的返回值。我们可以约定 lowestCommonAncestor 的返回值含义发生微小的变化：

  • 原含义：返回最近公共祖先。
  • 扩充后的含义：在子树里找 p 和 q。
  • 如果都没找到，返回 NULL（相当于 find 返回 false）。
  • 如果找到了其中一个（比如 p），返回那个节点 p（相当于 find 返回 true，且顺便带回了节点位置）。
  • 如果找到了最近公共祖先，返回那个祖先节点。

思维转换：

不要只返回“是/否”，而是直接返回“找到的那个东西”。这样 NULL 代表没找到，非空 代表找到了。

台阶三：模拟“汇报机制” (The Bubble Up)

现在我们假设自己是树中间的一个节点 root，我们派出左右两个递归去搜寻。根据它们回传的结果，我们来做决策。

这时候，你的脑海里应该有这样一个决策表：

左边回传 (left) 右边回传 (right) 当前节点 (root) 的推断 决策 (return)
有东西 (比如 p) 有东西 (比如 q) 哇！p 在我不远处左边，q 在我不远处右边。那我就是交点！ 返回 root (我就是答案)
有东西 NULL 左边找到了 p (或 p和q的祖先)，右边啥也没有。 说明答案在左边，把 left 往上交
NULL 有东西 左边啥也没有，右边找到了 q (或 p和q的祖先)。 说明答案在右边，把 right 往上交
NULL NULL 下面全是空的，没戏。 返回 NULL

221.最大正方形

一个正方形，一定要满足其左上方的点的右边以及下边和右下角都是1，以此就可以判断是否是正方形了，同时更大的正方形只需要遍历其右下角即可。实现起来发现有点问题，没有考虑到下方是否构成一个正方形，还是利用的信息少了，此时已经很接近动态规划的思想雏形了。

动态规划定义好dp[i][j]，其代表以位置i，j为右下角的正方形大小，据此推出

$$dp_{i,j}=\begin{cases}0,&matrix_{i,j}=0\\\min(dp_{i-1,j-1},dp_{i-1,j},dp_{i,j-1})+1,&matrix_{i,j}=1\end{cases}$$

小技巧，不想判断边界情况可以把dp矩阵第一行第一列左右各加新行新列。

238.除了自身以外数组的乘积

一开始肯定想的是暴力，遍历两遍就可以，但是这样会超时，因为时间复杂度为$n^2$了，所以得想办法优化，在逻辑上将数组变成一个矩阵，我们只需要对下三角和上三角分别乘就可以了，这样我们前面得遍历也好理解。

优化时，我们发现有很多我们其实是重复访问过得，因此可以用动态规划的思想，或者说递推，比如下三角，a[i]表示位置i左侧的乘积，那么a[i+1]=a[i]*nums[i]，这样我们就可以在O(n)复杂度下访问完下三角，同理，上三角也可以同样处理，从右下角往上递推！

148. 排序链表

刷题第一步，审题，理解题意，把握题目特征，本题是链表，有个麻烦的点在于只能线性访问。然后是想满足题意的算法，这里数值不大，可以用映射到数组的哈希法，但是空间复杂度不满足要求；时间复杂度是nlogn，那么肯定是需要二分出现树才能有logn。

既然要二分，就肯定要找到中间点，链表中找中间点都是用快慢指针，然后参照归并排序的思想就可以完成，构建三个函数，一个函数用于融合两个链表，一个函数用于排序好左右，一个查找中点。

找中点：快慢指针，对于奇偶链表，有没有一个比较优雅的方法找到中点，我当前的做法是判断快指针，如果其下一个或者下下个就是空，那就停。这里有个范式，但凡写while循环都要考虑结束条件，写for循环就考虑结束状态，保证和理想中的一样。

合并函数：对两个链表维护两个指针，当且仅当两个指针都不为空时循环继续，一旦有一个为空就跳出循环，将剩下的链表拼到末尾即可。这里使用一个小技巧，构造一个头指针，之后新的只需要连到它后面即可，最后返回它的下一个。

排序左右：先找中点，然后注意断开中点之后的，接着将左右分别调用合并函数即可，在这里就需要考虑到特殊情况，这样写后续合并函数就可以知道特殊情况是否能满足。

在各种需要预测的地方都会见到LRU缓存，今天也算是自己实现一次了。

首先是容量，这个容易，结构体中维护一个常数即可，进一个新的就减少一个，为0后每次进都需要去掉一个旧的。还有查找和放入，查找要求是常数时间，那就只能是使用哈希表了。放入可以先查找，没有的话就直接塞入，有的话改变值即可。最后是结构体该如何设计，要存储大量的数，无非就是数组或者链表，在这里链表比较方便，又为了能够方便插入和取出，双向链表最合适了，额外维护一个头节点，对于取出和插入都很方便。

首先是哈希函数，这个我不太熟悉，力扣里提到一个uthash库，是最流行的开源实现。如果是要自己实现，就要先理解hash的思想，其通过一个函数（这个函数通常已经固定，有经过检验的几个效果很好的函数），再就是冲突处理函数（所以结构体里要存储key，因为可能因为冲突，不是唯一映射），最后实现增删查操作即可。

如下是我写的屎山代码，没有拆分出函数，后续维护非常困难，一旦出现bug将是毁灭性灾难，所以一开始就应该先把大致框架打好再去实现具体细节，这样就知道所需要用的函数以及它们之间的公共点。后一个为ai重构的，确实简洁多了。

142. 环形链表 II

考研时刷的算法题又来了，还是不会做，这次记得是和跑圈有点像，用双指针，但是推不出来想要的，主要原因是没有想通它们一定会相遇，快指针的步数永远是慢指针的步数的两倍，所以当慢指针走了一轮，快指针一定走了两轮，并且由于环的存在，快指针肯定走在前头了。其二是列方程的时候，我假设慢指针走了a+nb（a为到环的距离，b为环的长度），快指针对应为两倍，再一减去等于tb（即套的圈数），但这是没法解的方程！因为未知量太多了，但是如果设慢指针走s，快指针走2s，相减得s=nb，这样就知道相遇点在离出发点nb处，此时只需要慢指针再走a，快指针从头开始就一定会相遇，有两次相遇就说明一定有环，就可以终止了。

看题解，动态规划两件套——先定义子问题，然后写状态转移方程。子问题是这样想出来的，假设我已经拿到了最优解，那我最后一步做了什么，这题就是最后做了右边某部分的匹配，那子问题就是除掉这个最后一步剩下的，即左边部分能否匹配上。划分完子问题，就要考虑当前问题如何从更小的子问题得到了，这题我们可以枚举字符串的长度，前j个匹配上的话，看后i-j个是否能匹配上，如果能，当前i就可以匹配上，后续再考虑更大的问题就可以直接使用上i的结果了，这也是当前dp相比于上面纯递归做法的优势。

注意，我们是用过去的信息，所以分割一定是从i旁边开始的，而不是另一端，另一端开始的话会限制我们使用的过去信息。

322. 零钱兑换

典型dp问题，和爬楼梯有点像，定义子问题为当前金额能否组成，那么父问题与子问题的联系就是，父问题减去提供的钱等于子问题，如果子问题可以成立，那么父问题肯定也成立。

这题需要返回的是最小硬币数，因此可以维护一个二维数组，一行表示当前金额可以组成，一行表示当前金额最小可以几枚组成，再一思考，发现干脆合并成一行就行了，如果是0表示不能组成，如果非0，值代表可以由几枚硬币组成。

递推的写法暂时没有想到，感觉比较麻烦，不如直接递归。

直接纯递归失败了，超时了，比如存在1的话就会递归很深，时间过长。于是想到从大的先找起，一旦找到就退出（这里隐藏一个前提，尽可能用大的去组成一定是最少的），但显然不对，比如1，10，20，25去组成30，显然最少是2，但是如果先选25，就需要6个，还是得回到剪枝。

分析可以知道，超时的原因是存在很多信息的重复获取，比如5可以由5个1组成，但是遍历15和25的时候，依旧还是要遍历到最深处才可以得到答案，导致很多重复的操作。因此需要加上记忆化搜索，即拿一个数组存储好已经得到的信息，递归+记忆化和递推有点像。

写记忆化搜索时框架很乱，导致有很多bug，问了ai，让他给我一个框架，写起来才顺利

记忆化搜索的“万能通用模板”

为了帮你建立框架，我总结了一个**“记忆化搜索五步法”**。以后遇到任何需要记忆化的递归（零钱兑换、爬楼梯、打家劫舍），直接套用这个结构：

框架结构

  1. Base Case（递归出口）： 越界了怎么办？到底了怎么办？
  2. Lookup（查表）： 之前算过吗？算过直接返回。
  3. Init（初始化局部变量）： 准备一个变量记录“当前这一层”的最优解（最大或最小）。
  4. Loop（遍历决策）： 尝试每一个可能的选择（选硬币A、硬币B…），更新局部变量。
  5. Memoize & Return（记账并返回）： 循环结束，把最终结果写入表，然后返回。

438. 找到字符串中所有字母异位词

一开始没有啥思路，看灵神的题解了解到滑动窗口，去做了一道简单题目，掌握了，回来一看，诶，该如何判断当前窗口的是否匹配所给字符串呢？想的最多的是使用哈希，但是又没办法区分eff和eef，于是阻塞住了，再看题解代码，发现原来就用两个数组存出现次数，然后比较内存就可以（忘记memcmp这个东西了）。

注意memcmp第三个参数是比较的字节数，滑动窗口框架就是进、更新、出，其实就是窗口先出再进再更新。

还有个变长窗口，利用抵消的想法，右边进就抵消上面代码中的b对应位置，左边出就加回去，只要某个字母出现过多就滑走，因为窗口中有不在所给串中的字符（这也是我一开始的思路，但没有一个很好的办法保证数组b不变）

437. 路径总和 III

一看就想左右递归，分别判断左右加起来等于所给值或者所给值减当前节点值，退出条件为目标值为0或者遇到空间点，前者返回1，后者返回0.但是这样有个问题，可能会选取不连续的路径。

分析后，只要选了当前值，就只能一条路走到黑，如果没有选当前值，则可以有多个选择。突然发现小bug（printf真好用），到了叶子节点，其左右都是空值，只要当前节点传入目标值0，就都会满足，但其实只有一条路径，所以不能把虚拟节点加进来。退出条件改为目标值与当前值相同或者左右都为空，但这样会出现一旦路径满足条件就退出了，而没有继续试探后续。

同时存在大量重复的访问，没有利用好历史访问信息，考虑使用栈保存，但还是没想到办法解决问题。

最后采用层序遍历加一条路走到底的思路，因为要使用队列，所以就用python写，用deque舒服，同时上述提到的没有继续试探后续，这样改进，遇到空节点返回0，遇到当前值等于目标值，count加一，后续count加上左右返回的值，最后返回count，为啥我没有想到呢？

560. 和为 K 的子数组

这题是上一题的简化版本，还是只会暴力做法，能够察觉到过往的信息没有办法使用上，也想过设计数组来存储信息，但是一是因为数太多，存储空间太大（为什么总是想不到用哈希表节省空间呢？数组本身就是一个hash表），二是往dp上面去想的，一直把问题分为当前值选与不选这样，没有察觉到其实是一个区间问题，可以使用前缀和。也不能这么说，一开始看到数组也想过用前缀和，但是依然要一次次遍历，O（n^2）的复杂度，想不到哪里还可以优化，于是就没有往这个思路去想了，但是看题解发现，首先把前缀和的式子变成s[i]=s[j]-k，这样我们就只要去找前缀和为s[i]的区间即可，找到了就说明存在一个区间，同时我们计算前缀和的时候可以把已经计算出来的值存到hash表中，key为值，value为出现次数。这样就可以在线性时间内找到想要的区间了。

提高

  • git merge main 将main上的修改以及git记录都融入到当前分支，会出现很多跳跃关系，开发记录很复杂
  • git rebash main 将当前分支开发记录接到main的最新节点上，一般只在自己的私人分支上使用，如果出现冲突，解决完后可以使用git rebase –continue继续，或者–abort放弃

  • git rebase -i [基准commit] 整理commit信息，合并多个
  • git reset –soft/mixed/hard commit_id 三个参数依次为移动head指针，保存代码与暂存区重新commit；保存代码，清空暂存区；全部回退
  • git reflog 最后的黑匣子
  • git revert commit_id 把有问题的commit反向抵消，适用于代码已经合并到生产环境

进阶

  • git stash /git stash pop 将工作目录与暂存区所有打包起来，避免切换分支失去；pop为取出代码
  • git cherry-pick commit_id 将目标提交复制到当前分支
  • git bisect 二分查找出问题的提交

实践

交互式变基，允许穿越回过去的某个时间点，重新编排从那时起到现在的所有提交，可以把很多琐碎的提交合并，pick为保留，squash为合并到上一个提交；解决完冲突后，使用命令继续变基；一旦不想变基了，abort放弃所有回到开始变基前。
