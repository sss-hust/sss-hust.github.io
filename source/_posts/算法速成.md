### [21. 合并两个有序链表](https://leetcode.cn/problems/merge-two-sorted-lists/)

快速熟悉链表操作，复健。

**当你需要创造一条新链表的时候，可以使用虚拟头结点简化边界情况的处理**。

```c
/**
 * Definition for singly-linked list.
 * struct ListNode {
 *     int val;
 *     struct ListNode *next;
 * };
 */
//新链表有一个头指针，有一个tmp指针表示当前最后的节点，依次拼接
struct ListNode* mergeTwoLists(struct ListNode* list1, struct ListNode* list2) {
    struct ListNode* head=calloc(1,sizeof(struct ListNode));
    struct ListNode* tmp=head;
    while(list1 && list2){
        if(list1->val<list2->val){
            tmp->next=list1;
            list1=list1->next;
        }
        else{
            tmp->next=list2;
            list2=list2->next;  
        }
        tmp=tmp->next;
    }
    if(!list1) tmp->next=list2;
    else tmp->next=list1;
    return head->next;
}
```

### [86. 分隔链表](https://leetcode.cn/problems/partition-list/)

```c
/**
 * Definition for singly-linked list.
 * struct ListNode {
 *     int val;
 *     struct ListNode *next;
 * };
 */
//
struct ListNode* partition(struct ListNode* head, int x) {
    struct ListNode *head1,*head2,*tmp1,*tmp2;
    head1=calloc(1,sizeof(struct ListNode));
    tmp1=head1;
    head2=calloc(1,sizeof(struct ListNode));
    tmp2=head2;
    while(head){
        if(head->val<x){
            tmp1->next=head;
            tmp1=tmp1->next;
        }
        else{
            tmp2->next=head;
            tmp2=tmp2->next;
        }
        head=head->next;
    }
    tmp2->next=NULL;
    tmp1->next=head2->next;
    return head1->next;
}
```

### 2.1 滑动窗口与双指针的几何哲学

滑动窗口技术是双指针方法的一种特化形式，专门用于解决数组或字符串中的连续子序列（Subarray/Substring）问题。其核心在于将嵌套循环的暴力搜索转化为两个指针（左边界$L$和右边界$R$）在数轴上的单向蠕动。

#### 2.1.1 变长窗口的伸缩机制

对于求解“满足特定条件的最小/最大子数组长度”这类问题，滑动窗口展现出了类似生物肌群伸缩的特性。右指针 $R$ 负责探索未知的领地，通过不断右移纳入新元素，试图寻找可行解；而左指针 $L$ 则负**责优化解的质量或维持约束的有效性**，通过右移收缩窗口来剔除冗余元素。

**原理深度解析：** 这种方法的有效性建立在“单调性”假设之上：如果区间 $[L, R]$ 满足条件，且我们要寻找最短区间，那么对于固定的 $R$，任何 $L' < L$ 的区间 $[L', R]$ 必然也满足条件（假设条件具有单调性，如子数组和大于某值），但长度更长，因此无须考虑。这种逻辑剪枝使得 $L$ 和 $R$ 都只会单调向右移动，互不回头。由于每个元素最多被 $R$ 指针访问一次，也被 $L$ 指针访问一次，算法的均摊时间复杂度严格控制在 $O(N)$。

**复杂状态维护：** 在实际应用中，窗口内的状态维护往往是难点。例如，在“包含所有字符的最小子串”问题中，我们需要引入哈希表（Hash Map）或频率数组来实时记录窗口内字符的分布情况。每当 $R$ 引入一个新字符，更新哈希表及“达标字符计数器”；当条件满足时，$L$ 尝试收缩，同时更新哈希表。这里的关键在于利用哈希表的 $O(1)$ 查询特性，确保窗口滑动的每一步操作代价恒定。

#### 2.1.2 定长窗口与差分思想

当问题限定窗口大小固定为 $K$ 时，滑动窗口退化为一种即时的差分更新机制。窗口从 $[i, i+K-1]$ 滑动到 $[i+1, i+K]$ 的过程，本质上是执行了一次“减去头部元素 $A[i]$，加上尾部元素 $A[i+K]$”的增量操作。这种思想不仅避免了重复计算，更暗示了差分数组的雏形。

相比于暴力，运用上了之前计算过的信息，因此更快。

### 2.2 单调栈与单调队列：剔除冗余信息的艺术

如果说滑动窗口是利用了区间端点的单调移动，那么单调栈（Monotonic Stack）和单调队列（Monotonic Queue）则是利用了元素值的单调性来剔除“无效”的候选项，从而实现极速查询。

#### 2.2.1 单调栈与最近更优元素

单调栈主要用于解决“寻找数组中每个元素左边/右边第一个比它大/小的元素”（Next Greater Element, NGE）这一类问题。

**冗余剔除原理：** 假设我们需要寻找每个元素右边第一个比它大的值。在遍历过程中，如果我们维护一个单调递减的栈，当遇到一个新元素 $X$ 时，如果 $X$ 大于栈顶元素 $Top$，那么对于 $Top$ 来说，$X$ 就是它一直在等待的“下一个更大元素”。此时 $Top$ 的使命结束，可以出栈。更重要的是，对于后续的元素而言，$Top$ 既然小于 $X$ 且位于 $X$ 的左侧，那么它永远不可能成为后续元素的“下一个更大值”（因为 $X$ 会先被遇到且更大）。因此，将 $Top$ 移除是安全的。通过这种机制，每个元素仅进栈一次、出栈一次，将 $O(N^2)$ 的暴力比较压缩至 $O(N)$。

这一结构在直方图最大矩形面积（Largest Rectangle in Histogram）问题中发挥了极致作用，通过维护高度递增的单调栈，我们可以精准地确定每个高度条能够向左右延伸的极限边界。

#### 2.2.2 单调队列与滑动窗口最值

当面临“滑动窗口最大值”问题时，普通的队列无法以 $O(1)$ 时间给出最值，而堆（Heap）则需要 $O(\\log K)$。单调队列（通常使用双端队列 Deque 实现）应运而生。

**索引存储与双端操作：** 单调队列内部存储的是数组的**索引**，而非数值。这不仅仅是为了获取数值，更是为了判断元素是否滑出了窗口边界。队列中的索引对应的数值必须保持严格单调递减（求最大值时）。

1. **入队维护：** 当新元素 $Val\_i$ 准备从队尾入队时，队列中所有小于等于 $Val\_i$ 的元素都将变得毫无意义——因为 $Val\_i$ 不仅比它们大，而且比它们“年轻”（生存期更长）。因此，将这些“老弱”元素从队尾弹出，直到队列恢复单调递减性。
2. **出队维护：** 检查队头索引是否已经小于 $i - K + 1$（即滑出窗口），如果是，则从队头弹出。
3. **结果获取：** 队头索引对应的元素即为当前窗口的最大值。

这种设计巧妙地结合了时序（索引限制）与大小序（单调性），确保了在窗口滑动的动态过程中，最值查询始终为 $O(1)$。

### 2.3 前缀和与差分数组：离散微积分的应用

在处理静态数组的区间查询与区间修改问题时，前缀和与差分数组体现了数学中积分与微分的对偶关系。

#### 2.3.1 前缀和（Integration）

前缀和数组 $P$ 定义为 $P[i] = \\sum\_{k=0}^i A[k]$。它将区间求和问题转化为两个前缀和的差值计算：$Sum(L, R) = P[R] - P[L-1]$。这一操作将 $O(N)$ 的求和降维至 $O(1)$。 在二维空间中，利用容斥原理（Inclusion-Exclusion Principle），我们可以构建二维前缀和来快速计算任意子矩阵的元素和。公式 $Sum(r1, c1, r2, c2) = P[r2][c2] - P[r1-1][c2] - P[r2][c1-1] + P[r1-1][c1-1]$ 精确地剔除了多减去的区域并补回了重叠扣除的部分。

#### 2.3.2 差分数组（Differentiation）

差分数组 $D$ 定义为 $D[i] = A[i] - A[i-1]$。它专注于解决“区间修改”问题。若要将区间 $[L, R]$ 内的所有元素增加 $V$，在原数组中需要遍历更新，而在差分数组中，只需执行 $D[L] += V$ 和 $D[R+1] -= V$ 两个操作。这是因为 $D[L]$ 的增加会随着前缀和的累积传播到 $L$ 之后的所有元素，而 $D[R+1]$ 的减少则在 $R$ 之后截断了这种传播。 这种方法将 $O(N)$ 的区间修改降低为 $O(1)$，最后通过对 $D$ 求前缀和即可还原修改后的数组 $A$，极其适合处理离线的批量区间更新任务。

## 3. 层次结构的递归与分治：树与图的高级算法

树与图结构是非线性数据的核心表达形式。在面试中，除了基础的 DFS/BFS 遍历，更高级的考察点集中在对复杂连通性、路径优化以及区间信息的层级化管理上。

### 3.1 树形结构的区间管理：线段树与树状数组

当数组不仅需要区间查询，还需要**动态**点更新或区间更新时，前缀和数组失效了（更新代价 $O(N)$）。此时，我们需要引入基于树形结构的对数级解法。

#### 3.1.1 树状数组（Fenwick Tree / Binary Indexed Tree）

树状数组是一种极其精妙的隐式数据结构，利用整数二进制表示中的 `lowbit` 特性来组织数据的层级依赖。

* **二进制索引原理：** 索引 $i$ 的节点不仅仅存储 $A[i]$，而是存储以 $i$ 结尾、长度为 $lowbit(i)$ 的区间的和。例如，索引 $12 (1100\_2)$ 存储区间 $[12 - 4 + 1, 12]$ 即 $[9, 12]$ 的和。
* **更新与查询：** 更新操作通过不断添加 `lowbit` 向上爬升至父节点（覆盖该位置的更大区间），查询操作则通过不断减去 `lowbit` 向下累加前缀区间。两者的复杂度均为 $O(\\log N)$。
* **局限性与优势：** 相比线段树，树状数组空间常数更小（$O(N)$ 空间），代码极其简洁（仅需几行位运算）。但它主要擅长处理前缀和性质的问题（可逆运算，如加法、异或）。对于区间最大值/最小值等不可逆操作，虽然可以魔改实现，但效率和直观性不如线段树。

#### 3.1.2 线段树（Segment Tree）与懒惰传播

线段树是解决区间问题的“瑞士军刀”。它将数组递归地二分为左右子区间，直至叶子节点代表单个元素。每个内部节点维护其子区间的聚合信息（Sum, Max, Min, GCD 等）。

* **懒惰传播（Lazy Propagation）：** 这是线段树处理**区间更新**（Range Update）的核心技术。当需要更新区间 $[L, R]$ 时，我们不再愚蠢地递归更新到底层叶子节点（这将导致 $O(N)$ 复杂度），而是只更新完全被 $[L, R]$ 覆盖的最高层节点，并给这些节点打上一个“懒标记”（Lazy Tag），表示“我的子孙节点还没更新，欠着账呢”。只有当后续查询或更新需要进入这些节点的子树时，才将标记下放（Push Down）一层。这一机制保证了区间更新和查询均维持在 $O(\\log N)$。
* **空间代价：** 线段树通常需要 $4N$ 的数组空间来存储树结构，这是其相对于树状数组的主要劣势，但换来了处理任意满足结合律运算的强大灵活性。

### 3.2 并查集（Union-Find）：集合的动态连通性

并查集（DSU）专门用于处理不相交集合的合并（Union）及查询元素所属集合（Find）的问题。它在图论中用于最小生成树（Kruskal 算法）、无向图环检测及连通分量计数。

#### 3.2.1 路径压缩与按秩合并

朴素的并查集可能退化为链表，导致 $O(N)$ 的查询时间。必须引入两大优化：

1. **路径压缩（Path Compression）：** 在执行 `Find(x)` 寻找根节点的过程中，递归地将路径上经过的所有节点直接挂接到根节点下。这使得树的高度在一次操作后急剧扁平化。
2. **按秩合并（Union by Rank/Size）：** 在合并两棵树时，总是将较矮/较小的树嫁接到较高/较大的树上，防止树高无谓增长。

**阿克曼函数的逆函数：** 当同时应用这两种优化时，并查集操作的均摊时间复杂度为 $O(\\alpha(N))$，其中 $\\alpha$ 是反阿克曼函数。阿克曼函数增长极快，因此其反函数增长极慢。对于宇宙中任何实际规模的 $N$，$\\alpha(N) \\le 4$。因此，在工程实践中，我们认为并查集操作是近乎常数时间 $O(1)$ 的。

### 3.3 图的最短路径：从贪心到动态规划

图的最短路径算法展示了算法设计策略的多样性。

#### 3.3.1 Dijkstra 算法

Dijkstra 本质上是基于贪心策略的广度优先搜索（BFS）变种。

* **原理：** 使用优先队列（最小堆）维护“当前已知距离源点最近的非确定节点”。每次从堆中取出距离最小的节点 $u$，并对其邻居进行“松弛”操作（Relaxation）：如果通过 $u$ 到达 $v$ 的距离比已知更短，则更新 $v$ 的距离并将其入堆。
* **限制：** 由于其贪心本质（一旦节点被从堆中弹出，就认为找到了最短路），Dijkstra **无法处理负权边**。负权边的存在可能破坏已经确定的最短路性质。

#### 3.3.2 Bellman-Ford 与 SPFA

Bellman-Ford 算法基于动态规划思想，其核心是对所有边进行 $V-1$ 次松弛操作。

* **原理：** 在一个含有 $V$ 个顶点的图中，任意两点间的最短路径（不含环）最多包含 $V-1$ 条边。因此，重复 $V-1$ 轮对所有边的松弛，必然能将最短路径信息传播到所有节点。
* **负环检测：** 如果在第 $V$ 轮松弛中，仍有边的距离被更新，则说明图中存在负权回路。
* **SPFA（Shortest Path Faster Algorithm）：** 是 Bellman-Ford 的队列优化版本，只将那些被更新了距离的节点入队，从而减少无效的松弛尝试。但在最坏情况下（稠密图或特殊构造的网格图），SPFA 会退化为 $O(VE)$。

#### 3.3.3 Floyd-Warshall 算法

Floyd-Warshall 是解决多源最短路径问题的经典动态规划算法。

* **状态定义：**$DP[k][i][j]$ 表示从 $i$ 到 $j$，仅允许以节点 $1 \\dots k$ 作为中间节点的最短路径长度。
* **状态转移：**$DP[k][i][j] = \\min(DP[k-1][i][j], DP[k-1][i][k] + DP[k-1][k][j])$。这一方程说明，加入节点 $k$ 后，最短路径要么不经过 $k$（保持原样），要么经过 $k$（从 $i$ 到 $k$ 再到 $j$）。
* **空间优化：** 可以将第一维 $k$ 去掉，直接在二维数组上迭代更新。注意循环顺序必须是 $k$ 在最外层，确保在使用 $k$ 作为中间点更新 $(i, j)$ 时，$i \\to k$ 和 $k \\to j$ 已经是基于 $1 \\dots k-1$ 优化过的路径。

## 4. 动态规划的深层建构：状态压缩与矩阵幂

动态规划（DP）并非简单的填表，而是对问题状态空间（State Space）的有向无环图（DAG）遍历。每一个 DP 状态就是一个节点，转移就是边。

### 4.1 状态压缩 DP（Bitmask DP）

当问题的状态涉及集合的选择，且集合大小较小（通常 $N \\le 20$）时，我们可以使用整数的二进制位来表示集合状态。

* **旅行商问题（TSP）：** 状态定义为 $DP[mask][i]$，表示已经访问了 $mask$（二进制位为 1 表示已访问）中的城市，且当前停留在城市 $i$ 的最小代价。
* **子集遍历技巧：** 在状态转移中，经常需要遍历一个掩码 $m$ 的所有子集。高效的代码范式是 `for (s = m; s; s = (s-1) & m)`。这个循环利用位运算巧妙地跳过了非子集状态，将遍历所有状态的所有子集的总复杂度从 $O(4^N)$ 降低到 $O(3^N)$（这是基于二项式定理的求和结果）。

### 4.2 数位 DP（Digit DP）

解决诸如“在区间 $[L, R]$ 中有多少个整数满足性质 X”的问题。

* **构造思想：** 利用前缀和思想，转化为 `Count(R) - Count(L-1)`。
* **状态设计：** 通常包含 `(index, tight, leading_zeros,...)`。其中 `tight` 约束至关重要，它指示当前位的枚举是否受到了上界数字的限制。如果 `tight` 为真，当前位只能枚举到 $0 \\dots N[index]$；否则可以枚举 $0 \\dots 9$。这种记忆化搜索避免了对每个数字的单独判断，直接按位构造符合条件的数。

### 4.3 矩阵快速幂与线性递推优化

对于 $N$ 极大（如 $10^{18}$）的线性递推问题（如斐波那契数列、爬楼梯），$O(N)$ 的线性 DP 无法通过。

* **矩阵化：** 如果状态转移方程是线性的（如 $F\_n = A \\cdot F\_{n-1} + B \\cdot F\_{n-2}$），我们可以构造转移矩阵 $M$，使得 $\\begin{bmatrix} F\_n \\\\ F\_{n-1} \\end{bmatrix} = M \\times \\begin{bmatrix} F\_{n-1} \\\\ F\_{n-2} \\end{bmatrix}$。
* **快速幂：** 根据结合律，$\\begin{bmatrix} F\_n \\\\ F\_{n-1} \\end{bmatrix} = M^{n-1} \\times \\begin{bmatrix} F\_1 \\\\ F\_0 \\end{bmatrix}$。利用二进制拆分思想（Binary Exponentiation），可以在 $O(K^3 \\log N)$ 时间内计算出 $M^n$，其中 $K$ 是矩阵的大小。这是解决超大规模线性递推问题的唯一途径。

## 5. 字符串算法的自动机与哈希美学

字符串问题常常涉及模式匹配。除了基础的 Trie 树，KMP 和 AC 自动机代表了确定性有限自动机（DFA）的应用典范。

### 5.1 KMP 算法：失配信息的再利用

KMP 算法的核心在于当模式串 $P$ 与文本串 $T$ 在某处失配时，不要将文本串指针回溯，而是利用已经匹配的部分信息，将模式串向右滑动到合适的位置。

* **前缀函数（Next/Pi 数组）：**$\\pi[i]$ 表示子串 $P[0 \\dots i]$ 的最长相等真前缀与真后缀的长度。
* **构造逻辑：** 计算 $\\pi$ 数组本身也是一个 DP 过程。求 $\\pi[i]$ 时，我们比较 $P[i]$ 与 $P[\\pi[i-1]]$。如果相等，则 $\\pi[i] = \\pi[i-1] + 1$。如果不等，我们通过 $j = \\pi[j-1]$ 递归地寻找更短的候补前缀，直到匹配或归零。这种“利用自身匹配自身”的思想是理解 KMP 的关键。

### 5.2 AC 自动机：多模式串的终极武器

当需要在一个文本中同时查找多个模式串时，对每个串跑一遍 KMP 极其低效。Aho-Corasick (AC) 自动机将所有模式串构建成一棵 Trie 树，并在 Trie 树上添加了类似 KMP 的“失败指针”（Failure Link）。

* **失败指针构建：** 使用 BFS 遍历 Trie 树。对于节点 $u$ 的子节点 $v$（字符为 $c$），其失败指针指向 $u$ 的失败指针所指向节点的子节点 $c$。直观地说，如果我们在 Trie 树的某个深处失配了，失败指针会把我们要么带到另一个模式串的最长前缀，要么带回根节点。
* **图的转化：** 添加了失败指针的 Trie 树实际上变成了一个包含环的有向图（DFA）。在匹配过程中，指针在图中跳转，永不回溯文本串，实现了 $O(Len\_{Text} + TotalLen\_{Patterns})$ 的最优复杂度。

#### [15. 三数之和](https://leetcode.cn/problems/3sum/)

三数之和可以通过排序后转化为两数之和，本题关键在于如何保证不重复。排序后枚举每一个数，再去其右侧（因为不考虑顺序，所以三元组里不可能有比左端数更小的，否则就是之前枚举过的）找后续数能否找到一个两数之和满足三数相加为0。如何保证不重复呢？我们可以先考虑什么情况下会重复，也就是当前三元组满足后，枚举下一个数和之前的数一样，这种情况就会导致出现相同的三元组，因此直接跳过它就可以了。

```python
class Solution:
    def threeSum(self, nums: List[int]) -> List[List[int]]:
        #先排序，然后枚举每一个数，在其右侧找两数之和，遇到相同的就跳过
        nums=sorted(nums)
        i=0
        res=[]
        n = len(nums)
        while i < n-2 :
            j = i+1
            k = n - 1
            while j < k :
                if nums[i] + nums[j] + nums[k] > 0 :
                    k-=1
                elif nums[i] + nums[j] + nums[k] < 0 :
                    j+=1
                else :
                    res.append([nums[i] , nums[j] , nums[k]])
                    k-=1
                    while j < k and nums[k] == nums[k+1] :
                        k-=1
                    j+=1
                    while j < k and nums[j] == nums[j-1] :
                        j+=1
            i+=1
            while i < n-2 and nums[i] == nums[i-1] : 
                i+=1
        return res
```

```python
        return ans
```

```python
        #思路：依旧先排序，然后遍历每一个数值，在其右侧寻找两数之和最接近的数，用一个最小值维护全局即可
        nums=sorted(nums)
        mn=13001
        ans=0
        for i in range(len(nums)-2):
            x=nums[i]
            j=i+1
            k=len(nums)-1
            while j < k :
                diff = x + nums[j] + nums[k] - target
                s=x + nums[j] + nums[k]
                if diff == 0 :
                    return target
                #如果当前三个数和更小，更新全局最小值与最小差值
                if abs(diff) < mn :
                    ans = s
                    mn=abs(diff)
                #如果和更大，就变小的，否则变大点
                if diff > 0 :
                    k-=1
                if diff < 0 :
                    j+=1
        return ans
```

#### [11. 盛最多水的容器](https://leetcode.cn/problems/container-with-most-water/)

先使用暴力法再考虑如何优化，暴力就是一个双层循环。优化有两个方向——先看有没有扫过一遍但是没有利用上的信息，比如第一次循环时，其实可以知道从起点到不同区间的和，可以考虑如何将这些信息组织起来；再看是否有情况是没必要考虑的，比如左端点下一处更矮，那就一定不可能形成更多水。跳到刚刚扫过时记录下的第一个最高点，接着再向右查找。最终还是超时了。

```python
        high=0
        i=0
        while i < len(height)-1:
            index = i
            time = 0
            high = height[i]
            for j in range(i+1,len(height)):
                if height[j] >= high and time == 0:
                    index= j
                    time = 1
```

本来想靠自己做出来的，发现还是熟悉度不够，这题依旧可以使用相向指针，从两端开始向中间前进，同步记录全局最大水量，同时，如果想要更大的水量，只有可能把两端变得更高，同时由于水桶效应，把两端更矮的变得更高，收益最大，于是就这样左右矮的先动，不断找最大值。选对方向就是快。。。几行就搞定了，不用那么多弯弯绕绕的判断。

```python
class Solution:
    def maxArea(self, height: List[int]) -> int:
        ans = 0
        left = 0
        right=len(height)-1
        while left < right :
            x = min(height[right],height[left])
            ans = max(ans,x * (right - left))
            if height[right] <= height[left] :
                right-=1
            else :
                left+=1
        return ans
```

#### 复盘

第一种思路其实是贪心的做法，单纯寻找“更高的点”并试图跳跃时，只关注了高度，却忽略了**宽度**的巨大权重。有时候两个很矮但隔得很远的点，面积反而巨大。单纯跳过中间的点，可能会漏掉“矮但宽”的最优解。为了修补这个逻辑，必须加很多 `if/else` 来判断各种边界情况，导致代码逻辑复杂且容易出错。

之前也想过宽度和高度的关系，比如减小宽度，但增大高度，水会不会变多？发现不一定，于是就不好判断减小宽度增大高度可以把所有情况枚举完。但其实可以这样理解：

双指针的本质不是“寻找”，而是“安全剪枝”。我们可以把所有可能的 $N^2$ 种组合看作一个矩阵。每一次比较 left 和 right，我们实际上是在划掉一整行或一整列。因为短板效应的存在，不可能存在比当前组合更大的值了（在宽度减小的情况下）。

所以这题关键在于将宽度和高度两个变量变成单调的，比如宽度从大到小（右指针从最右遍历），要想有更多水，高度就一定要增加，增加到什么时候就不会变了呢？一直到右端比左端更高（短板效应），于是之后的情况就都不用考虑了，左端遍历下一个，同时由于对称性，右端也是如此，因此两端都不用回去，只需要不断前进就可以。

```python
class Solution:
    def trap(self, height: List[int]) -> int:
        left,right = 0,len(height)-1
        max_l,max_r = 0,0
        ans=0
        while left <= right :
            #更新左右最大值
            max_l=max(max_l,height[left])
            max_r=max(max_r,height[right])
            #计算短板桶存的水，看下一个位置
            if height[left] <= height[right] :
                ans+=max_l-height[left]
                left+=1
            else :
                ans+=max_r-height[right]
                right-=1
        return ans
```

### Day4 [二分查找 红蓝染色法【基础算法精讲 04】\_哔哩哔哩\_bilibili](https://www.bilibili.com/video/BV1AP41137w7/?spm_id_from=333.788.videopod.sections&vd_source=dc20802858710b0f360a7d6d042a7509)

```python
def find_lowbound(nums:List[int],target:int)->int :
    # 此函数用于寻找有序数组中开始大于等于target的下标
    # 采用闭区间写法
    # >可以转化为找大于等于target+1
    # <=可以转化为找大于等于target+1
    # <可以转化为找大于等于target
    left = 0
    right = len(nums)-1

    while left <= right :
        # 循环不变量为：left左边一定是比target更小的，right右边一定是大于等于target的
        # 由于一开始也要符合这个要求，如果从right开始是大于等于target，那么一开始就无法保证满足
        # 闭区间的精髓在于双向挤压，左区间是更小的，右区间是大于等于的
        # 当两者交汇说明整个空间已经遍历完了，因此可以退出，再根据我们的需要返回所需。
        middle = (left + right) // 2  
        if nums[middle] < target :
            left = middle + 1
        else :
            right = middle - 1  
    return left
```

#### [2080. 区间内查询数字的频率](https://leetcode.cn/problems/range-frequency-queries/)

二分查找需要进行排序，如果需要对子数组进行二分排序，每次都重新拷贝数组及排序，时间复杂度等于扫一遍了，因此必须在原数组上进行操作，但原数组一旦排序就会打乱索引。针对以上问题，可以用字典记录下要找的数的索引，然后在这个列表里去进行寻找，这样就能保证有序且无需重复拷贝数组。

```python
class RangeFreqQuery:

    def __init__(self, arr: List[int]):
        pos=defaultdict(list)
        for i, x in enumerate(arr):
            pos[x].append(i)
        self.pos = pos
  
    def find_lowbound(self,nums:List[int],target:int)->int :
        # 此函数用于寻找有序数组中开始大于等于target的下标
        # 采用闭区间写法
        # >可以转化为找大于等于target+1
        # <=可以转化为找大于等于target+1
        # <可以转化为找大于等于target
        left = 0
        right = len(nums) - 1
        while left <= right :
            # 循环不变量为：left左边一定是比target更小的，right右边一定是大于等于target的
            middle = (left + right) // 2  
            if nums[middle] < target :
                left = middle + 1
            else :
                right = middle - 1  
        return left
    def query(self, left: int, right: int, value: int) -> int:
        nums = self.pos[value]
        l = self.find_lowbound(nums,left)
        r = self.find_lowbound(nums,right+1) - 1
        if r<l:
            return 0
        return r - l + 1
```

```python
            # 更新第二个列表
            tmp2 = tmp2.next
            # 第一个列表继续连接
```
